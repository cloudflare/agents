`AIChatAgent` and `Think` run chat recovery through one shared sequence. A recovery no longer continues a reply that a client's tool result already continued (the incident ends `skipped` with `continued_by_interaction`), an attempt that throws ends with `onExhausted` (`recovery_error`) in `AIChatAgent` too, a stop always ends the incident as `user_cancelled`, an incident that gave up is no longer marked failed, a turn that is interrupted while another turn's recovery waits now gets its own incident instead of being filed as a later attempt of that recovery, a transient stream error that reaches recovery waits as long as the provider's `Retry-After` or `retry-after-ms` asks (up to 60 seconds), and in `Think` a live interruption that `onChatRecovery` declines to continue now ends the turn with the stream's own error instead of a generic message. A recovery attempt that hits a platform transient now leaves its incident `scheduled` (with `deferredError`, and no `chat:recovery:failed` event) until the same attempt runs again, so a stop or a client's answer in between still reaches it. A stop by any request id the client can hold (the original request, the incident's current one, the recovered turn's own) ends the incident `skipped` with `user_cancelled`, and so does a recovered turn that returns `aborted`. A turn declined inside a recovery attempt emits one `chat:recovery:skipped` event and no `failed` after it. `onChatResponse`, the turns it starts and a continuation timer created during a recovered turn no longer run as part of the recovery attempt. A recovery callback that is delivered again after an isolate reset cut its turn off no longer continues the reply a second time (the incident stores `scheduleCount` and `startedDelivery`, and the callback payload carries `delivery`). `Think` continues a cut-off turn whose stream a reconnecting tab closed before recovery ran, where it used to end it `skipped` with `stream_terminal`, and no longer marks that turn's submission `completed`. `Retry-After` is also read from inside the AI SDK's `RetryError`, so it survives the SDK's own retries. In `AIChatAgent`, the terminal record of a recovery that gave up during a live stall is kept when the stalled turn then ends.
