`agents/tasks` becomes one durable state-machine engine with two APIs, and the engine ships as its own entry point, `agents/state-machine`.

`agents/state-machine` exports `StateMachine`, the Lifecycle capability that owns the run tables, the wake stream and routed dispatch, registering machine definitions only, under a `StateMachine`-prefixed vocabulary (`StateMachineDefinition`, `StateMachineContext`, `StateMachineRunHandle`, `StateMachineOptions`, `StateMachine*Error`, plus `defineAsk`). `Tasks` now extends `StateMachine` — same tables, same handles, one capability instance — adding the durable-function form, compiled onto the engine as it is registered, and keeping every `Task*` name as an alias of its `StateMachine*` type (each `Task*Error` is the same class). `Agent` still installs only `this.tasks`; a machine registers through `taskDefinitions` or `this.tasks.register()`. Storage tables and event types keep the `task` namespace. One observable change: the engine errors' runtime `name` (as persisted in a failed run's `error.name` and seen in `onError`) now reads `StateMachine…` rather than `Task…`; `instanceof` under either alias is unchanged.

The Workflows-shaped step API is unchanged — `(input, step) => result`, replay from the first line, `step.do`/`sleep`/`sleepUntil`/`status`/`idempotencyKey`/`signal`/`attempt`/`interrupted`, `NonRetryableError`, run `deadline` and `interruptions`. A step definition is compiled onto the engine as a single-phase machine whose one handler replays the function, on the same journal, with byte-identical step idempotency keys: there is no second journal, no second claim path, and no second abort protocol.

Alongside it, a definition may now be a durable state machine: `{ initial, phases, onCancel?, migrate? }`. `initial` is the first checkpoint — a value, or a function of the run's seed. `phases` holds one handler per phase, `(state, ctx) => next`, keyed by the state union's `phase` discriminant: it receives the durable checkpoint, does work, and returns the next one. Returning is the commit, one generation-fenced row write. Annotate the definition `satisfies TaskMachine<State, Mailbox, Result, Seed>` and each handler's state narrows to its own phase; no helper function, no registration step. `ctx` is the per-handler runtime, and it EXTENDS `step` — the same object, widened with a durable mailbox, correlated durable asks (`defineAsk`), `memo`, owned children, engine-owned streams, and progress credit.

Also: `run(name, input, { start, background, turnTimeout })` chooses who drives a run's first attempt — `warm` (the default), `queued`, or `attached`, which drives it in the caller's invocation and resolves at its next durable boundary — and `register(name, definition)` returns a `TaskInternalHandle` whose `run(input, { start })` is the one way to start a reserved `__cf`-prefixed definition. The `__DO_NOT_USE_WILL_BREAK__runAttached` and `__DO_NOT_USE_WILL_BREAK__enqueue` apertures are removed; every in-repo host and harness now starts its reserved definitions through the handle `register()` returns. `AIChatAgent` and `Think` gain a protected `_reservedTask(name)` accessor for those handles, and their `_enqueueChatRecovery` is now protected, so a subclass can queue a recovery run without the apertures. `tasks.at(name, runId)` returns a per-run typed handle beside the `handle(name)` lens, which is now typed by its definition, so the machine verbs are `never` — uncallable — on a function definition. `cancel(runId, reason?, { wait? })` can await terminality rather than acceptance.

Schema version 3 adds the checkpoint, turn, progress, transition, abort-mark, parent, background and stream-epoch columns to `cf_agents_task_runs` by plain `ALTER TABLE ADD COLUMN`, adds mailbox, ask and routed-owner tables, and rebuilds `cf_agents_task_steps` as `cf_agents_task_journal` keyed by `(run_id, turn, name)`. Host SQL that reads the old table name must follow the rename. The rebuild runs in batches under a durable cursor at an intermediate version, each batch in its own transaction, and no definition dispatches until it completes; an object with nothing to rebuild skips it and stamps version 3 directly. A requested cancellation becomes the run's abort mark. In-flight runs migrate at turn 0 and resume from their journals; nothing is reset. Objects holding a large retained journal should call `tasks.delete({ settledBefore })` before upgrading, since the rebuild copies every retained row once.

**Two type changes:** `TaskWaitReason` widens to `sleep | retry | interrupted | mailbox | event | ask | child | paused`, and `TaskRunSnapshot`'s `waiting` arm makes `wakeAt` OPTIONAL, because a run parked on a mailbox, an ask or a child has no wake time and reporting `updated_at` as a future wake was wrong. The `running` and `waiting` arms gain `abortRequested`/`abortReason` for the window between a `cancel()` taking the mark and the run settling. `TaskRunState` keeps its six values; `faulted` and `orphaned` ride a new `outcome` field beside `failed`.

New exports on `agents/tasks`: the machine types (`TaskMachine`, `TaskContext`, `TaskDefinition`, `TaskDefinitions`, `TaskPhased`, `TaskTerminal`, `TaskTimedOut`), the extractors (`TaskInput`, `TaskOutput`, `TaskState`, `TaskMailbox`), the handles (`TaskHandle`, `TaskRunHandle`, `TaskInternalHandle`, with `Task` kept as the two-parameter alias), the mailbox, ask, stream, spawn and change types, `defineAsk` with `AskKind`/`Pending`, `AssertJson`, `MAX_CHECKPOINT_BYTES`, and the new errors `TaskNoProgressError`, `TaskTransitionBudgetError`, `TaskTurnDeadlineExceededError`, `TaskCancelCannotParkError`, `TaskConcurrentParkError`, `TaskEventTimeoutError`, `TaskMailboxFullError`, `TaskCheckpointTooLargeError` (a `TaskSerializationError`) and `TaskOrphanedDefinitionError`.

Children and streams: `ctx.spawn(definition, input, { background?, notify?, ...run options })` accepts a child run whose settlement lands in the parent's mailbox as a `kind: "child"` note, `ctx.join(children, { within })` is sugar over receiving those notes, cancelling a parent cascades to its in-tree children (background children are detached), and `terminate` takes the children with it. `ctx.stream(name?)` opens an engine-owned stream — `${runId}:${name}#${epoch}`, tagged `${runId}:${name}` — that settles in the same transaction as the next checkpoint, is sealed and rotated when a lost attempt is reclaimed, and credits its appends as progress; pass the `Streams` capability as `streams` in the Tasks options. `view()` reports the run's streams. Cross-facet children (`spawn(..., { owner })`) are declared but refused in this release.

Review round two: a machine run's transition watchdog defaults to the step timeout (off for a durable function) and is enforced on routed runs too; a terminal the fence refuses consumes no mailbox items; a duplicate `requestId` is refused before `latest` can clear the original; ask ids and default child run ids derive from the turn so a replayed transition finds what it already raised or spawned; a park re-checks for a send or answer that raced it; `reopen()` accepts any failed or cancelled run whose row is still present.

Breaking, experimental surface.
