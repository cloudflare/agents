Stopping the turn that is running now also drops the auto-continuations that were waiting when the stop landed, in `AIChatAgent` and `Think`, however it is stopped (the client's cancel, `abortRequest`, `abortAllRequests`, `cancelAllChats`, or the `signal` passed to `saveMessages`, `continueLastTurn` or `chat()`): a tool result answered while the reply streamed, or one that arrived while a continuation ran before it was stopped, no longer starts the model again; it stays in the transcript, `chat:continuation:dropped` is emitted with reason `stopped`, and a result that arrives after the stop continues as usual. `abortAllRequests` and `cancelAllChats` drop every waiting continuation whether a turn is running or not (one in its coalesce window, parked on an unanswered tool call, or `Think`'s queued connection-less one), and `abortRequest` with the id of the reply that just ended drops the continuation waiting to continue it. The stop button now reaches the server while a tab waits for a tool continuation to start: the client sends `cf_agent_chat_request_cancel` with `continuation: true` and no `id`, and the server stops the continuation that connection waits on. In `chat:continuation:dropped`, `requestId` is the continuation's own id (`null` for a result dropped before it had one) and the new `stoppedRequestId` is the turn whose stop dropped it. `Think`'s WebSocket cancel now also aborts a running recovery attempt directly, as `cancelChat` does.
